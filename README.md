# Incubator

이물 검출 모델을 **실험하고, 데이터를 먹여 학습시키고, 메인 앱(CleVisionSystems)에 넣기 전에 검증하는** 툴.
지원 알고리즘: PatchCore(이상탐지), YOLO(검출).
설계: `docs/superpowers/specs/2026-10-28-incubator-design.md`

## 설치
```
py -3.11 -m venv .venv
.venv\Scripts\python -m pip install torch==2.5.1 torchvision==0.20.1 --index-url https://download.pytorch.org/whl/cu121
.venv\Scripts\python -m pip install -e .[dev]
```

## 실행
```
.venv\Scripts\python -m incubator
```
- 첫 실행 때 PatchCore 백본(wide_resnet50)과 YOLO 사전학습 가중치(`~/.incubator/weights`)를 내려받는다 — **인터넷 필요**.
- 데이터셋(경로·라벨·박스)은 `~/.incubator/datasets/<이름>.json`에 저장된다. 이미지는 복사하지 않는다.

## 데이터셋 만들기
- **새로 만들기 (폴더 스캔)**: 루트 폴더 + 파일 패턴(예: `*/cam_03_IMG_Texture_8Bit.png`) + 마스크. 그룹 = 회차 폴더. 처음엔 전부 미분류.
- **폴더 가져오기**: `normal/ inside/ edge/`처럼 나눠 둔 폴더를 하위 폴더 → 라벨로 매핑. 파일 이름 필터는 `;`로 여러 개(`*__LH.png;*retake*`).
- 마스크와 크기가 다른 이미지는 만들 때 알려주고 뺀다. 원본이 옮겨져 없는 파일은 열 때 알려주고 실행에서 뺀다.

## 사용법 — 3단계
1. **알고리즘** — PatchCore(이상탐지) 또는 YOLO(검출) 카드를 고른다.
2. **데이터 준비** — 위 데이터셋 바에서 저장된 데이터셋을 고르거나 새로 만들기 / 폴더 가져오기. 아래에서 라벨링.
   - `N` 정상, `I` 간섭, `U` 미분류, `←/→` 이동, 드래그로 박스(그리면 간섭), 박스 클릭 후 `Delete`
   - 분할 고정: 항상 학습 / 항상 평가 (예: 손글씨 판은 학습, 어려운 정상은 평가)
   - 미분류는 학습·평가에서 빠진다.
   - PatchCore는 박스가 선택(그리면 위치 적중 계산), YOLO는 박스 있는 간섭 2장 이상 필수. 준비가 안 되면 위쪽 ③ 탭이 막히고 탭 옆에 이유가 뜬다. 단계 이동은 위쪽 탭을 누른다(이전·다음 버튼 없음). 알고리즘 카드를 누르면 바로 ②로 간다.
3. **학습·결과** — 왼쪽 파라미터(항목마다 조정 힌트, 바꾸면 결과 지워짐, 학습 중엔 잠김: PatchCore 입력 폭 640 · 메모리 20,000 · 마스크 침식 5px / YOLO 모델 n/s · epoch 30 · 겹 수 3 · 입력 640), 오른쪽 학습 / 중단, 성적표 한 줄(놓침·오검출·AUC·임계값·위치 적중(YOLO만)·처리 시간)과 그 옆 모델 내보내기, 임계값 슬라이더 + 직접 입력 + `자동`, 점수순 이미지 목록(놓침 빨강, 오검출 주황), 원본 | 히트맵(또는 예측 박스).

- 정상은 학습 60% / 임계값용 20% / 평가 20% (같은 회차는 같은 쪽). 자동 임계값 = 임계값용 정상 점수 최댓값 바로 위, 놓침·오검출은 **처음 보는 평가 세트**에서 센다.
- 실행 중에는 이전 단계·데이터셋 변경이 막힌다. 결과는 실행 시점 데이터 사본 기준이다.
- 데이터나 파라미터를 바꾸면 결과가 지워진다. 결과는 저장하지 않는다.
- 실패·중단 사유는 성적표 자리에 남는다.
- **이미지별 위치 보정**: 마스터 파일(`…_IMG_Kungfu.png`) 옆에 마스터 이미지(`…_IMG_Texture_8Bit.png`)가 있으면, 이미지마다 마스터와의 평행이동을 재서 마스크를 옮겨 쓴다(FEM LH: 중앙값 16px, 최대 38px 밀림). 미리보기·결과 화면 아래에 보정량과 신뢰도가 나온다. Source LH(정상 86·간섭 4)에서 PatchCore AUC 0.926 → 0.956.

## 모델 내보내기 (현장용)
③ 학습이 끝나면 성적표 옆 **📦 모델 내보내기**를 눌러 폴더를 고른다. 방금 학습에서 검증한 모델을 그대로 내보낸다(재학습하지 않음).
`{데이터셋}_{알고리즘}_{날짜-시각}/` 폴더가 생긴다.

| 파일 | 내용 |
|---|---|
| `manifest.json` | 임계값(내보낼 때 슬라이더 값), 이미지 크기, 위치 보정 영역, 전·후처리 값 |
| `model.onnx` / `fold1~k.onnx` | PatchCore 1개 / YOLO 겹별 모델(현장 점수 = 최댓값) |
| `mask.png`, `score_mask.png`, `master.png` | 판정 영역, PatchCore 침식 마스크, 위치 보정 기준 이미지 |
| `report.json` | 지표·장수·파라미터·검증 결과 |

- 내보낸 직후 ONNX로 다시 채점해 화면 점수와 비교한다. 결과 줄에 `검증 일치 n/n`이 나오면 현장 코드가 같은 점수를 낼 수 있는 묶음이다. 불일치는 주황색으로 경고한다.
- 채점 순서의 기준 구현은 `incubator/runtime.py`(torch 없음, onnxruntime + OpenCV)이다. C# 연동은 이 순서를 그대로 옮긴다. 형식은 [설계 문서](docs/superpowers/specs/2026-10-29-model-export-design.md) 참고.
- FEM P2 LH 실측(2026-10-29): PatchCore 묶음 약 225MB(model.onnx 222MB), 내보내기 2초, 검증 65장 일치·최대 차이 6e-6. YOLO 3겹 묶음 약 40MB(겹당 12.8MB, 입력 544×640), 검증 정상 52장 일치·최대 차이 6e-8.
- YOLO는 툴의 `.pt` 예측과 같은 rect 레터박스 크기로 내보낸다. 정사각 640×640으로 내보냈을 때는 점수가 최대 0.019 달라 검증에서 걸렸다. ultralytics 버전은 8.4.191로 고정한다.

## 첫 검증 (2026-10-28, FEM P2 LH)
데이터: `C:\DATA\EV\FEM\clip\anomaly\data` 가져오기 — 정상 127, 간섭 15, minor 미분류. 기존 HARD_NORMAL 4건 항상 평가, 손글씨 판 항상 학습.
분할: 학습 77 / 임계값 25 / 평가 25.

| | 놓침 | 오검출 | AUC | 자동 임계값 | 처리 시간 |
|---|---|---|---|---|---|
| PatchCore | 0/15 | 5/25 | 0.976 | 2.553 | 68 ms |
| (기존 스크립트, 80/20, 임계값 수동 2.65) | 1/15 | 0/30 | 0.998 | 2.65 | - |

- 같은 이미지 점수는 기존과 거의 같다(cabletest__2 3.81→3.84, cabletest__7 2.58→2.62) → 이식 정상.
- 오검출 차이는 평가 방식 차이다. 기존에 학습에 들어가 있던 정상(260326_094107 3.03, 260325_160107 2.89 등)이 이번엔 평가로 가면서 드러났다. 정상 이미지가 더 필요하다는 신호.
- YOLO: 간섭 15장에 박스가 아직 없어 미실행. ② 데이터 준비 목록에서 간섭 사진을 고르고 오른쪽 사진에 박스를 그린 뒤 실행.
